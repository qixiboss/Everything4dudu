# 优化方案：进入应用不再等待"验证账户"，页面立即渲染

## 现状与瓶颈

每个应用页加载时，`site/shared/hub.css` 用纯 CSS 立即隐藏整个页面并显示"正在验证账户…"全屏遮罩。遮罩要等 7 个 defer 脚本（含 211KB 的 Supabase SDK）全部下载并执行到 `auth-gate.js` 才算"验证完成"。验证本身只是本地读 localStorage（毫秒级），用户感受到的等待其实绝大部分是脚本下载时间——已登录用户也被白屏挡住。

## 目标

保持现有登录门禁不变：未登录仍跳回门户登录页。已登录用户（本机存有会话，绝大多数场景）进入应用零等待：页面立即渲染、本地数据立即可用，验证在后台进行，云端同步照旧后台激活。不剥离 Supabase SDK，不改变脚本加载契约。

## 改动内容

### 1. `site/shared/hub.css` — 移除遮罩阻塞（核心）

删除两条规则，其余样式保留：
- `html[data-app]:not([data-auth-ready]) body { visibility: hidden; }`
- `html[data-app]:not([data-auth-ready])::before { content: "正在验证账户…"; ... }`

`data-auth-ready` 属性在 auth-gate.js 中保留设置（向后兼容、测试可断言），但不再控制页面可见性。

### 2. `site/shared/auth-gate.js` — 后台验证 + 本地会话启发式

验证逻辑保持不变：`HubAuth.init()` 有会话 → 设置 `data-authenticated`/`data-auth-ready`；无会话 → `requireLogin()` 跳回门户。改动只有一处新增：

- 当 `HubAuth.init()` 返回 `null`（未登录或 SDK 加载失败）时，先读本地会话缓存 `localStorage['supabase.auth.token']` 做启发式判定：若存在未过期的本地会话（`currentSession.user` 且 `expires_at` 未过期）→ 视为"验证暂不可用但本机已登录"，设置 `data-auth-ready` 让用户留在应用使用本地数据（云端同步自然降级为失败重试）；无任何缓存痕迹 → 照旧 `requireLogin()` 跳转。
- 收益：① 离线/弱网时已登录用户不会被踢回门户卡死；② 未登录用户直接输入应用 URL 时，跳转前不再先闪出页面内容，语义更干净。
- 实现注意：从 `site/shared/vendor/supabase.js` 源码确认其 localStorage 存储格式（`currentSession` 结构），按实际格式解析；若无法可靠解析则仅以"是否存在非空缓存"作为判定依据。

### 3. `tests/portal.test.js` — 更新与新增测试

- 更新测试「每个应用仅在账户验证前锁定，云端同步在后台进行」（约 138-148 行）：改为断言 hub.css 不再包含 body 的 `visibility: hidden` 规则与"正在验证账户…"遮罩；auth-gate 仍保留 `requireLogin` 跳转逻辑、`data-auth-ready` 属性与 `hub:sync-status` 监听。
- 新增测试：用 vm 沙箱加载 auth-gate.js，模拟 `HubAuth.init()` 返回 `null` 且 localStorage 存在未过期会话缓存 → 断言设置 `data-auth-ready` 且不触发 `location.replace`；模拟无缓存 → 断言触发跳转。

### 不改动的部分

- `scripts/site-contract.js`、`scripts/check-integrity.js`：脚本加载顺序与标签不变。
- `site/shared/home.js`：门户对未登录点击的拦截与登录弹窗逻辑保持不变。
- `site/shared/hub-auth.js`：会话恢复、`lockAcquireTimeout` 等不变。
- 同步引擎、各应用自身 boot 流程均不变（数据同步本就是后台非阻塞的）。

## 验证

1. `npm test`（node --test 跑 tests/，含更新后的断言）
2. `npm run check`（完整性检查）
3. `npm run verify`（发布前契约验证）
4. 实现后可用浏览器实际打开门户与各应用页，确认：已登录进入无遮罩、无会话跳转正常、控制台无报错。

## 风险与对策

- 未登录用户直接访问应用 URL：验证期间会短暂看到页面骨架（低频场景，数据均为本机数据）；本地会话启发式落地后此闪烁基本消除。
- token 缓存格式兼容：以 vendor 包实际格式为准解析，解析失败时回退到"存在即放行本地模式"，不引入新的卡死路径。
- RLS 仍是权威数据边界，前端放行不影响数据安全。
